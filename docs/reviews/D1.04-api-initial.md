## 必须修正的具体规格缺口

### P2-1：权限逐维匹配及非Invoke所需权限缺实际安装字段

API 49–58、83–89、119–121行：ScopeRule有多个集合，但“不需要维度按use忽略”没有最终矩阵；OperationPolicyInput只有一份required_permissions，没有“查询/目录等用途显式安装所需permission”的实际结构。实现者无法确定GetSummary/CancelExecution等究竟检查什么政策，尤其owner预授权发生在scan前、此时没有目标或执行操作。

需要给出每种AccessUse的必需维度、operation是否可空、目标/owner/field匹配规则，以及非Invoke安装映射和查找来源。规定匹配保持整条规则的维度关联：例如同一来源两规则分别允许(target A, read)与(target B, write)，不能先各自并targets/permissions再推出(A, write)。每来源只合并已对当前完整请求tuple匹配的规则，然后四方交集。owner预授权可作为有限候选检查，逐项仍需实际目标/精确政策授权，不能通过scan前检查取代四方规则。

### P2-2：摘要端口看不到其必须覆盖的完整Group材料

API 167–175、188行：GroupSnapshot仅公开members()，但fingerprint合同要求包含envelope和anchor。外部派生TrustedGroupDigestPort没有权限读取这两个私有字段，无法满足已写出的摘要差异要求。

应提供精确只读envelope()/anchor_target()以及完整有序成员访问，或单一自有canonical材料访问；构造保持私有，禁止可变引用。成员序号可用span顺序定义，不必额外冗余字段。保留强制碰撞控制：摘要相等不能替代私有原始材料/发行实例验证。D1.04使用明确标识的确定性摘要消费者可接受，不需要冒充生产密码学后端。

### P2-3：传输缓冲与容量预留只有说明，没有可实现接口

API 255–258及270–278行：PreparedTransmission完全不透明，TransmissionStartPort没有读取字节的方法，也没有预留容量/消费预留的入口。派生sink既无法读取实际帧，也无法按合同提前保留容量，最终可能只能自报Started。

需冻结PreparedTransmission的只读字节span/长度/不可变归属访问、唯一创建者和owner交接，以及start_now所需的预留材料（例如端口发行的RAII reservation）。预留失败在仲裁外处理，实际首字节仍与撤权同一次短仲裁，禁止让保留票据代替真实传输起点。Started/NotStarted/Unknown的现有规则正确；补接口时不得放宽成返回token后延迟发送。

### P2-4：查询/分页响应没有对应发送起点接入口

API 284行要求get/list响应同样在发送前复验，但SendCoordinator只支持enqueue(WatchAuthorization, ChangeHint)。直接get/list返回摘要/Page不带可消费的响应发送归属，确定性consumer没有合法路径证明“查询后撤权、实际响应发送前”会拒绝，不能假造一个Watch替代响应授权。

应给出独立响应路径，例如由get/list生成私有拥有型ResponseAuthorization/PreparedResponse，绑定原会话、用途、实际目标/owner/字段、投影与期限，再由enqueue_response或等价接点进入同一start_next仲裁。或者给出完整可实现的等价签名。须明确返回的普通摘要只供同步调用消费，不是后续无限期发送许可；网络发送适配必须保有本次响应绑定，不能接收用户自填payload重新借摘要授权。

### P2-5：剩余私有类型/当前状态来源须补完整声明

计划已显式列出未定项，API尚缺WatchAuthorization的寿命/不可复制规则和可用只读接口、SessionAuthority::observations完整签名、PageBinding实际字段与restore身份来源。ExecutionAccessSourcePort当前没有restore元数据入口，不能把PageBinding写成“可用时绑定”却没有可比较的当前可信来源。PolicyAdministration具体方法也需给精确Result/所有权签名。

请补可按C++头声明核对的字段和入口，消除类型forward declaration遗漏、访问不可能和多继承Caller/Target两个PortLifetime分支的owner转换歧义。若D1.04不具restore源，可明确其为无restore配置，未来适配不可默默忽略已存在的restore身份。订阅配额及诊断数量也应有明确配置/计费口径，不能无限保留关闭连接或终结action的发行历史。

## 已符合的关键边界

每连接固定CallerAuthority、可信认证返回值而非请求自填事实、四方求交方向、私有原始permit发行、每动作独立PermitAuthority、组成员全部目标和生命周期复验、取消/撤权/消费同仲裁均符合规范。生命周期世代与ACL世代分离、资源lease只保活也正确。真实预分配内存sink证明首字节、Unknown不自动重试是可接受的本包消费者；OS管道/完整协议/生产索引/cursor密码学仍留后续，不提前宣称Runtime可用。

## 计划覆盖意见

计划35项覆盖认证来源、同主体不同连接、交集、多目标/组、许可并发、撤权/取消、字段/分页、队列及传输起点，范围与D1.04一致。216/216/218加35得到251/251/253，总755，算术正确，但均为候选预期。

计划列出的5项未定内容应先通过上述修订冻结。建议在既有four-way/查询/queued/传输项内补“规则tuple不可交叉拼接”和“get/list响应撤权后0字节”的具体子断言，公开只读材料/预留端口需正编译控制。不得因为名称已有35项就假定这些组合已被覆盖。
