## 五项关闭依据

1. UsePolicyInput明确非Invoke所需权限和用途模块规则；实际操作政策另行精确匹配。逐use矩阵区分target/owner/field的相关性，空集合不当通配。每来源必须以同一条规则完整匹配tuple，避免先并目标/权限形成不存在的组合；随后四来源求交。scan前owner检查只准有限候选扫描，不产生可见数据授权。
2. GroupSnapshot具有envelope/anchor/有序members只读访问，digest端可实际读取完整材料。安全仍依赖原始ActionAuthorization发行归属和私有完整成员/目标集合；强制摘要碰撞也不能借其他动作许可。
3. PreparedTransmission提供只读bytes/binding/projection；ProjectionEncoderPort及reserve→TransmissionReservation→start_now签名可实现。预编码和容量预留在锁外；reservation由真实端口发行并验证身份，capacity不是自报证明。Started要求在同一撤权仲裁结束前已有实际字节越过起点，Unknown不能重试，NotStarted必须证明零字节。
4. get/list返回原始ResponseAuthorization，enqueue_response只接收本会话真实发行对象，保存其内部投影，不接受调用方修改后的AuthorizedPage借权。响应不依赖伪造Watch；逐项当前授权在实际发送前复验，任一失权丢弃整个原字节响应。
5. PageBindingData和source.identity来源完整，Present/未知restore明确拒绝；不再静默忽略可用restore身份。Administration、Session端口、observations及Watch/Response私有State、创建者、不可复制规则和预算回收口径已经给出。Caller/Target改为两个单继承端口组合，避免PortLifetime转换歧义。

## 关键一致性核查

- 每连接固定SessionRecord和两个authority；VerifiedCaller、Target、Action、Response、Watch均核对原始发行归属而不是只比较Principal或DTO字段。相同主体不同连接仍独立，close不能取消其他连接或业务执行。
- Action许可逐成员、逐真实目标核对四方授权和生命周期；公开PermitBinding单anchor不替代私有多目标集合。current_expected_binding来自固定准备动作和当前可信记录，不来自待消费permit字段。
- 取消、消费、权限替换、委托收缩、close、目标事实更新共同短仲裁；消费成功不表示效果已发生。ACL、生命周期与资源锁没有合为一种许可。
- SessionRecord不反向拥有SessionAuthority/端口，ObservationAuthorization持记录而不持外壳；活动索引用weak或有界记录，避免Store→实体→Store循环。终结对象仍在途时继续计真实内存，不能仅移除索引就虚报释放。
- 锁内禁止分配、任意回调和大对象析构，与锁外预备/延迟回收配套；start_now是明确受审的非阻塞字节起点特例，不允许后端把工作丢给未仲裁队列后自报Started。此要求可由本包预分配sink实际验证，不要求实现生产OS传输。
- 统一输入独立拥有规则仍适用于编码端返回材料和私有投影：正文的vector移入不能被实现解释为允许保留外部可变元素别名。端口及freeze适配器的受信承诺不变，不宣称隔离恶意C++。

本轮批准不替代实现检查。后续必须以真实字节/消费计数、tuple交叉拼权反例、响应撤权、原始发行对象替换、分配异常、配额回收和身份/世代耗尽验证这些承诺；不得只靠私有类型名称或capability布尔值自证。

没有要求扩展OS认证、完整通知/游标密码学、生产执行索引或D2/D3后端。具体API与固定集合冻结后可按已授权流程进入行为实现；包级Passed仍须真实矩阵及独立代码审核。
