## 1. P2：Read 注册没有确定所绑定服务的选择键

位置：API 第4节 read/candidate_read 签名，以及“Reader类型必须匹配当前模块声明服务”。

允许两个直接依赖模块各提供一个相同 Reader C++ 类型的服务，ServiceRequirement 也以 module/service/type 区分它们，但 read 的参数只有函数、DefinitionInput 和仅包含资源的 OperationOptions。相同类型的两个真实 owner 可以返回完全不同内容，单凭 Reader token 无法决定 ReadServices 要保有哪一个。若实现选第一个或全局按类型选择，将使注册顺序改变业务依赖，违背固定绑定要求。

必须增加明确服务选择（如 module/service 的键或批次发行的受检绑定对象），或明确拒绝歧义及给出唯一性的规则。candidate_read 的原普通 Read 服务也必须沿同一选择。测试要包含“两个相同 Reader 类型、不同提供者/服务名”的绑定控制，不能只测类型错误。

## 2. P2：provider、资源和 executor 归属及精确声明未冻结完整

位置：第2节 ModuleManifest/ModuleInput，第4节 OperationOptions/candidate_read。

provider requirement 仅以“同样绑定声明提供者模块及精确key/type”描述，缺具体字段类型与在 ModuleManifest 中的成员；StateEdit/candidate 又只要求“当前模块已绑定真实provider”，没有定义操作如何选中依赖模块的 provider。OperationOptions.resources 只有 Name，而 ResourceRequirement 已用 module/resource；两个依赖同名资源时同样无法决定归属。ExecutorBinding 写“组合根提供”，ModuleInput 又称自有“以上提供项vector”，尚不明确 executor 是全批根级输入还是模块提供项、同名重复如何处理。

必须写出上述具体声明及选择/唯一性/依赖匹配规则，同时给出完整 ModuleInput 成员；不能留给实现按全局先遇到者解析。candidate_read 的“read函数指针”也应写成完整 C++ 签名，冻结 Reader/P/Args/R 的推导与选择参数。可在现有 provider_binding/execution_capabilities/atomic_candidate_contract 子断言补同名跨模块情形，无需为此创造工作包。

## 3. P2：配置普通值复制不足以保证不可变快照

位置：第2节 `ConfigurationBinding::make<T>(T value)`。

ContractValue 和可复制只验证语法及值合同，并不证明传递深拥有。反例 T 持有 `shared_ptr<MutableConfig>`：TypeContract 可正常验证且 T 可复制，make 的 const 副本仍指向调用者可修改对象。修改原对象会改变已登记配置，与正文“后续调用者修改原value不能改变配置快照”和计划的冻结所有权相矛盾。直接 move vector/string 时也须考虑调用者保留元素指针的别名规则。

必须明确支持的受审配置 carrier/深复制入口及其冻结承诺；可以采用 D1.02 相同的可信类型作者深拥有合同加专门适配，也可以限制至固定安全类型，但不能声称普通拷贝即普遍实现不可变性。至少补含可变共享成员的拒绝或深复制正控制，以及输入修改后读取实际已保存配置仍不变的验证途径。

## 4. P2：分配异常后的批次状态和不可吞错误顺序需明确

位置：第3节“所有失败为终结状态”和“分配异常可传播”，以及第4节内部粘性记错。

目前没有规定诊断分配、候选构造或深复制抛异常时，何时把批次置为 Failed/粘性失败，也没有明确该状态设置是否无分配且先于错误诊断构造。若 duplicate/非法注册已经判断失败，但在 error vector 增长时抛 bad_alloc，而模块 catch 后继续，台账可能尚未置位；若 publish 抛异常则还可能遗留 Validating 而 failed()==false。两种结果都与计划“不允许模块吞错”和草案自身终态声明冲突。

请冻结异常语义：一旦检测合同失败先执行不会失败的粘性置位，再尝试追加诊断；异常离开 add/publish/注册入口时本批不得再成功发布，候选仍RAII释放。可以传播分配异常且不包装业务错误，但必须说明如何保持终结状态与诊断截断事实。测试保留会返回的控制路径，使用确定性的分配/诊断故障注入验证，不以任意崩溃代替预期拒绝。
