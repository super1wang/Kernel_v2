决定：Approved。决定者：Codex AI，依据既有自动验收授权独立作出预算判断；不是测量程序自动按实测值乘系数/加余量，也不是 human Approved。预算原始数值、批准时间和方法摘要见根目录 `footprint-budgets.json`。

## 阶段上限及判断

以下均为固定小型 NativeSubset 场景的准入上限，单位 MiB（1 MiB=1048576 bytes），不声称覆盖所有用户预算配置。Private 与 Working Set 不求和；Debug/ASan 是诊断配置，不代替 Release 发布占用。

| 配置 | Private/Ready peak commit 绝对最大 | 配对增量最大 | Working Set/Ready peak WS 绝对最大 | 配对增量最大 | EXE 分发增量 |
|---|---:|---:|---:|---:|---:|
| Release | 16 | 4 | 64 | 8 | 4 |
| Debug | 64 | 16 | 128 | 32 | 16 |
| ASan | 512 | 128 | 512 | 128 | 32 |

Release 采用小型嵌入宿主可承担的低 MiB 级新增开销限制，较高绝对 Working Set 额度用于 Windows/CRT 共有驻留页；配对增量单独限制框架成本。Debug 为符号/诊断实现预留开发空间。ASan 明确容纳运行时 shadow/quarantine，不把该开销变成生产预算；同时保留 Release 严格额度及跨配置线程/分配硬约束。上述额度按阶段资源定位决定，pilot 用于检查可观测性、实现是否处在可接受数量级与异常归因，不自动生成上限。

Release 轻量时延上限：内部 Ready 绝对 250 ms、配对增量 100 ms；创建到 Ready 绝对 1000 ms、配对增量 250 ms。当前机器为 Windows 11 Insider 27749、i5-12600KF、32 GiB RAM，实际安全工具和负载快照已记录；创建/通知/采样协议包含调度成本。这是本阶段受控测量门槛，不是产品 P99/SLO，也不声称冷 OS 启动。将内部与创建时延分开，防止只选择较小指标。

新增 Native 线程在每对/每阶段必须为 0，成功完整调用窗口的新增分配每次必须为 0；两者不因诊断额度而放宽。所有预算指标都有明确 finite upper bound，若超限保持 Failed；不得自动抬线重跑。
