## 本轮发现及闭合

1. 原稿缺少真实 CandidateRead 绑定入口，仅描述 AtomicMode 不足以证明兼容。最终稿增加受检适配工厂、私有见证与实际 domain 核对。
2. 原稿没有 Outcome 的 BeforeApply/记录故障决定材料入口，RecordFailure 放在 ports 还会造成依赖方向问题。最终稿将 OutcomeConditions 等置于 outcome 层，并由 Outcome 工厂接收、保存及交叉验证。
3. 业务可先用自建 publication authority 构造合法形状 Outcome，再跨域转交。最终稿要求真实接收端完整 revalidate，并在 publication_proof_required 中固定“已构造伪域 StateCommitted 转交拒绝”的反例。
4. KnownFacts::appended 不能单独防止用 create 重建截短历史。最终稿增加 validate_facts_append，接收端必须用自己保存的旧事实，测试覆盖空、截短及改写集合替换拒绝。
5. 仅换真实 publication authority 仍不能识别没有 PublishedFact 的伪 CancelledBeforeApply。最终稿让 revalidate 显式接收 owner 自有 expected_conditions 和 previous_facts，validate_outcome_conditions 逐项核对决定、故障和计数；原 before_apply 用例增加伪 CancelWon 转交真实 NotReached/ClaimWon 接收端的拒绝子断言。

以上均已通过最终文本复读闭合；它们是待实现的固定正反合同，不是已运行的测试结果。
