# D1.05 结果运输适用条件增量

状态：待独立 AI 增量审核；不改写最初 API 审核或原始失败报告。

固定依赖 `tl::expected 1.1.0` 的 `expected_operations_base::construct_with` 使用无条件 `noexcept`；`expected_move_base` 的条件 `noexcept` 并不能使内部辅助函数的异常可捕获。对可抛移动的 R 执行 Result 运输，会进入 terminate；不能以 Invocation 外层 catch 宣称它可恢复。原始尝试保留于 `evidence/bootstrap/D1.05/pipeline-3c335c7a6787`。

本增量保持 Registry、CoreContracts 的 ContractResult 与依赖锁不变，只收窄本包 Native 同步绑定的可执行适用条件。NativeEngine::bind 在任何 typed bind、Policy 准备或业务调用之前，以 constexpr 检查 R（void 例外）、Result<R>、Outcome<R>、Result<Outcome<R>> 与 InvokeReply<R> 的移动构造均不抛出。不满足条件时返回 InvalidBinding，禁止进入业务；该类型仍可被 Registry 合法描述，不将它标为 Native 可执行。Args 和 R 实际校验器以及 Handler 的普通异常仍必须按进入前/后分界映射，不能借此跳过校验。

实现保留 FinalObservation 的栈退出统一记录，覆盖完整返回对象构造后才记一条最终状态。该逻辑不声称捕获 noexcept 违约或终止进程后的日志。

验收控制：可抛移动的注册结果必须 bind 拒绝且业务零进入；int、小定长 Value、owning string 的合法 Native 正例仍真实运行。额外子进程 `--throwing-transport-probe` 直接复现锁定 Result 运输的 terminate，终止处理器输出固定标记并以 86 退出，防止自动验收被系统错误对话框挂住。该子进程是依赖边界负控制，不能计作业务 Completed 或成功异常恢复。

本增量不改变 v3.3 A21.5 的固定小定长无分配场景，不扩展其他模块；独立 AI 审核与新一轮运行证据通过前，D1.05 仍 InProgress。

## void 路径修订

初版统一 trait 检查在 `pipeline-b4ce2aa7a9db` 的实际正控制中误拒绝 void，保留该失败。锁定后端 `expected_move_base` 直接使用 `is_nothrow_move_constructible<void>`，其 false 传播至上层 Outcome/Reply；然而 `expected_operations_base<void,E>::construct_with` 只设置成功标志，错误分支只移动 Error，没有 R 对象。

独立 AI `review_foundations` 已逐段核对该源码并批准 void 路径例外：void 且 Error 无抛出移动允许 Native 绑定；非 void 仍保留初版全部限制。补充 void 成功、业务错误和 Handler 异常三种实际调用，以及 unique_ptr 返回值成功控制。初版审核是历史设计事实，本段为后续修订，不将旧失败改写为通过。
