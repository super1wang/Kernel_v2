## 修订审核

初审四项 P2 均已在具体规格中闭合，未发现新的必须修订项。

1. read/candidate 现在必须通过完整 ServiceRef 显式选择依赖，禁止仅凭 Reader 类型猜选。两个模块提供相同 Reader 类型的控制例已纳入 service_binding。options 内无关 shape 字段明确拒绝，不会默默忽略错误依赖。
2. provider/resource/executor 全部用模块限定的 ref，ModuleManifest 的 required 集合、ModuleInput 的实际提供集合及 candidate_read 完整函数签名已经给出。跨模块必须有直接依赖和对应声明，同模块不要求自依赖；实际提供和声明必须完全匹配，重复项拒绝。executor 名称与 DefinitionInput 的名称核对，affinity/能力按明确选中对象核对。
3. ConfigurationSnapshot<T>::freeze 为显式、受审、无默认复制回退的深冻结合同；冻结输出再接受 TypeContract 校验。没有把 copyable 或 shared_ptr<const T> 误当任意对象图不可变证明。共享可变成员的真实深复制对照及无冻结器编译拒绝已在既有固定测试项内登记。
4. 入口检测失败后先无分配置粘性 failed 状态，再构造诊断；异常离开入口前也置失败，模块 catch bad_alloc 不可挽回批次。诊断分配失败不覆盖原失败，RAII负责候选清理，不强行要求内存不足时再成功分配错误记录。相应诊断故障反例明确保留。
