## 4. 现有 runner 的落实边界

继续使用 `ock.run-manifest/1`、`ock.expected/1`、`ock.evidence/1` 和 `ock.gate-matrix/1`，不新增 runner。`cases[].profiles` 支持上述适用配置；**checks 不按 profiles 过滤**（common.expected_cases / validate.audit），同一 expected 的三份 run 必须配置相同 CHECK 集合。因此本候选保留既有三个轻量 CHECK：`CHECK.dependencies.python`、`CHECK.conformance.bootstrap`、`CHECK.models.outcome_consistency`，各配置一次；不为避免这三个小检查改审计语义。

每份最终 run 必须绑定同一最终 commit、实际源集合摘要及依赖锁；开发快照、诊断旧lib复用、pilot和历史成功不能拼为最终来源。当前 gate 以 `(task_id,profile)` 选完整报告，既不支持把旧报告裁剪为新集合，也不支持只交部分子工件。

Logging 每次 CTest 读取期生成新 run_id；固定分配末项顺序依赖其他 11 项，再独立核验全部原始命令、退出、Job、流 SHA、编译标记及同轮身份。缺项或前项失败必拒绝，CTest DEPENDS 本身不构成资格。单独筛选末项且没有同轮其他项会拒绝；两后端共同五项成功后才分别具备资格，可选异步/file 职责因真实能力为 false 只记 NotApplicable。
