## 具体 API 审核必须落实的已有约束

以下是计划已承诺行为的核查点，不是新增工作包或阻断本计划的修改要求：

- 精确写出批次状态转换及粘性错误存储，明确在诊断分配失败、计数溢出及钩子异常后如何保持失败；不得把一个返回 Error 的辅助函数误当作不可吞错误台账。
- 明确 RegistryId/RegistryGeneration 的发行和稳定性，不能让调用方指定复用身份或把另一目录相同槽当原槽。目录冻结和 describe 所返回 owner 都须无可变别名。
- 明确提供服务/provider的实际类型、所有权及窄读取方式，批次验证不能把 capability 声明当作真实后端的认证证明。未具备动态 Schema 时按计划拒绝相应注册需求。
- 明确四种 shape 的实际 Handler 如何私有保有，既支持未来 D1.05 同一实现调度，又不向模块导出裸 Handler 或无类型服务查找。
