# D0.02 内核信任边界与威胁模型

依据 A02、A10、A16、A19–A23。本文件冻结设计边界，当前没有真实授权、IPC 或存储实现；不表示完成安全扫描或运行时安全认证。

## 资产与边界

| 边界 | 可信事实来源 | 必须维持的性质 | 责任包与验证 |
|---|---|---|---|
| 进程内 native 模块 | 宿主选择并加载的可信代码 | C++ private/Context 防误用，不能声称恶意 native 沙箱；Handler 不从 Registry 裸露给模块 | D0.02 include/DAG 负例；D1.02/D1.03 注册合同 |
| OS 客户端到本地 IPC | Win32 身份、服务端验证、显式 DACL | VerifiedCaller 由认证适配器构造；外部 principal/role/trusted 只是输入，不授予权限 | D1.04/D2.05 真 Named Pipe 正反测试 |
| 主体/会话/模块/目标到调用 | 服务端规则交集及解析后的实际目标 | 目录可见不等于执行许可，选择状态不能在后台漂移；内部自治用 ServicePrincipal | D1.04/D3.05/D7.03 |
| UI/Workspace 到业务 | 同一 Operation 注册/授权/提交面 | StateEdit、ExternalEffect、Lifecycle 不可直写旁路；已授权不可变快照可直读 | ADR-ui-operation-surface；D1/D4/D6 实际调用链 |
| AI/脚本到批准 | 可信批准绑定 PlanDigest/目标/输入版本/期限 | approved=true、文件内容、模型标签不能提权；变化或过期使批准失效 | D7.02/D7.03/D7.06 |
| 观察/枚举到调用者 | 当前 VerifiedCaller 与委托视图 | owner 只是过滤；发送前核验授权世代；隐藏计数/错误/退订不泄漏；已发送字节不可撤回 | D0.04-b、D2.04/D3.07/D7.05 |
| Host 到耐久存储 | 单活动写 Host、存储端口所有权 | 状态/回执/必要审计/Outbox 由唯一事务所有者提交，恢复保留未知事实 | D0.05/D5.01–D5.09 |
| SDK 到外部消费工程 | 受审查公开清单/声明及真实安装树 | 不泄漏私有第三方或本机路径，不把 ABI/未实现能力冒充承诺 | D0.02、D0.06、D8.01 |

## 威胁与反例

伪造角色、扩大 target/resource、复用过期批准、后台重新读取选择、跨主体猜测任务/订阅、撤权后发送排队数据、慢观察阻塞控制、状态万能 API 绕 Catalog、UI 直写、Runtime 反向链接 SQL/IPC、并行提交所有者、旧备份抹掉已发生外部效果均为需拒绝或保留未知事实的场景。

本包实际反例仅验证架构/声明规则及安装边界。身份仲裁、资源许可、真实 IPC/数据库/线程行为由上述责任包实现和测试；不得把静态守卫通过当作这些机制存在。

## 已知限制

同一 OS 用户的 AI 与人工天然共享该用户文件/进程权限；仅应用会话无法抵抗读取高权限凭据。需要此隔离时必须另行选用不同 OS 身份、沙箱或可信 broker，并单独验证。内核不提供热卸载、远程 OAuth、互联网监听、任意 Shell、硬实时设备安全或功能安全认证。设备急停和联锁属于设备安全层，不扩展到本阶段。
