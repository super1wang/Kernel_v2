范围仅含 Foundation 原语、基础布局/分配统计、公开头与安装消费者；不扩展 Runtime、GUI、CAD/CAM、设备、完整 Unicode 库、完整 expected 实现或自研 STL，不迁移旧代码/数据。

- `dependencies.lock` 固定 tl::expected 1.1.0，commit 为 `292eff8bd8ee230a7df1d6a1c00c4ea0eb2f0362`，CC0-1.0。已有 expected probe 覆盖 move-only、void、错误传播与 bad_expected_access，但不替代本包合同测试。

## 最小 API 与语义

公开入口建议为 `ock/foundation/foundation.hpp`，命名空间 `ock::foundation`。维持 header-only 的 `OCK::Foundation`；如体量需要拆头，每个公开头均进入 manifest、独立包含测试及安装集合。具体声明以下表为审查输入，不承诺已冻结 ABI。

| 原语 | 建议 API / 表达 | 合同 |
|---|---|---|
| Result | `template<class T, class E = Error> using Result = tl::expected<T, E>`；Unexpected/make_unexpected 使用后端别名或 using | 全 SDK 单一固定后端，不增加第二层 expected 容器，不改后端成功/失败/异常语义 |
| ErrorDomain / ErrorCode | 静态进程寿命域标识＋固定宽度数值；内建 Foundation 域；自定义域仅通过引用非类型模板参数入口 | 同域同码相等；构造、复制、比较无分配。使用 `template<const ErrorDomain& Domain>` 工厂实质拒绝栈域和临时域；禁用任意域指针/引用构造；域内名称限定静态字面量，不得卸载域代码 |
| ErrorInfo | 拥有型 UTF-8 诊断文本；受检构建入口 | 先检查有效性与字节预算，再分配；输入失效后详情仍有效；不引用 Payload |
| Error | ErrorCode＋可空 `shared_ptr<const ErrorInfo>` | 纯码包装不分配；详情不可变并拥有寿命；详情复制共享拥有权，不借用调用者内存 |
| Name | `Name::parse(string_view) -> Result<Name>`；固定 96 字节数组＋长度 | 1–96 字节且全部在 0x21–0x7e；拥有输入；按字节、大小写敏感比较；不归一化、不转小写 |
| Tagged128 | `template<class Tag> struct Tagged128`；16 字节值，TaskId/ObjectId 等为不同 Tag 别名 | 只有同 Tag 可以赋值/比较；没有跨 Tag 隐式转换；本包不提供生产随机身份生成算法 |
| 身份编码 | `parse_id<Tag>(string_view)` 与固定长度编码输出 | 32 位小写 hex 精确往返；拒绝非规范表达；解析成功不授予任何权限 |
| RegistryGeneration | 独立的 Tagged128 类型 | 表达 registry 世代，创建方必须保证不同 registry/世代不复用；不能用相同的局部递增数冒充跨 registry 唯一性 |
| BoundHandle | `BoundHandle<Tag>` 含 RegistryId、RegistryGeneration 和 slot/index；受检解析入口 | 先同时验证 registry identity 与 generation，再验证 slot 边界，错误不得索引容器；相同 generation 的其他 registry、旧世代和空句柄均拒绝 |
| RuntimeEpoch | 与稳定业务 ID 分离的强类型 | 不并入稳定 ID 的持久表达；需要递增时必须检查溢出，不能回绕 |
| 受检算术 | unsigned integral 的 checked_add/sub/mul、checked_narrow；排除 bool | 运算前检查，不执行已知会溢出的计算；失败返回码，源值不变 |
| CheckedCount | `try_add` / `try_sub` 等先检查后修改入口 | 适用于长度、计数及累计预算；失败保持原值，值的转换同样检查 |

建议 ErrorInfo 文本初始上限为 4096 字节，这是待审查实施常量，不是架构原文规定的数值；更严格的调用方结果预算仍须生效。超限拒绝，不静默截断多字节字符。UTF-8 验证仅检查编码合法性，包括截断序列、overlong、surrogate 与超出 U+10FFFF；不实现完整 Unicode 功能。名称和显示文本的类型/入口分开，中文显示合法不代表中文注册名称合法。

错误详情分配的 `std::bad_alloc` 自然传播，不改写为可重试业务失败；用户提供类型的异常遵循后端和类型本身的异常保证。错误 Result 的 `.value()` 保留 `tl::bad_expected_access`。不变量破坏使用明确 fail-fast 入口，不制造普通业务错误；测试在独立子进程验证。不得为可能分配的详情构建入口无依据标注 noexcept。

当前无需要用户重新决定的规范冲突。主代理可在实施前固定 4096 字节预算、空句柄表示、索引宽度和公开函数拼写。RegistryGeneration 的唯一性由后续注册生命周期负责；D1.01 只提供类型、比较与校验原语，不伪称已有实际 registry 管理器。

|---|---|
| T03.foundation.code_only_no_allocation | ErrorCode、纯码 Error、成功/失败 Result<int> 与 Result<void> 构造、复制和传播均无包装分配；计数器用一次显式分配校验灵敏度 |
| T03.foundation.value_operations_no_allocation | Name 解析/复制、Tagged128 解析/编码与句柄比较无分配；输入与输出缓冲预先准备 |
| T03.foundation.layout_statistics | 输出 ErrorCode、ErrorInfo、Error、Result<int>、Result<void>、Name、Tagged128、BoundHandle 的 sizeof/alignof；只对 Tagged128 的128位表达等真实合同断言，不伪造全部 ABI 冻结 |
| T04.foundation.result_move_only_value | unique_ptr 成功值可移动、移动后目标保留内容；不可复制性用编译期断言验证 |
| T04.foundation.result_move_only_error | move-only 错误可移动并保留错误内容；不意外要求 E 可复制 |
| T04.foundation.result_void | void 默认成功及错误构造/传播正确；无值成功路径不访问不存在的值 |
| T04.foundation.result_error_propagation | and_then 成功调用一次；失败不调用，保留域、码和拥有型详情 |
| T04.foundation.result_bad_access | 失败的 value() 抛准确 bad_expected_access 并保留错误；正常值不抛 |
| T04.foundation.exception_not_business_failure | 抛异常的用户类型与注入 bad_alloc 被外层准确观察；不转换成 Result 业务错误，不因吞异常继续成功 |
| T04.foundation.static_error_domain | 静态域工厂正常编译；栈域、临时域和任意域指针入口编译失败；失败测试验证编译诊断而不是启动失败 |
| T04.foundation.error_details_ownership | 来源字符串销毁/修改后详情保持原文；Error 复制和移动后拥有权有效；空详情不生成分配 |
| T04.foundation.error_details_budget | 恰好上限字节成功；上限+1拒绝且不先分配超额文本；不能用 UTF-8 字符数量代替字节预算 |
| T04.foundation.display_utf8 | ASCII、中文和合法四字节字符通过；截断、非法 continuation、overlong、surrogate、超出码点上限拒绝 |
| T04.foundation.checked_arithmetic | 加法/乘法边界值、零、减法正例通过；max+1、乘积溢出、0-1拒绝；所有失败无未定义溢出 |
| T04.foundation.checked_narrowing | 目标最大值与零通过；目标最大值+1拒绝；bool不符合公开模板约束 |
| T04.foundation.checked_count_atomic_update | 合法累计后得到精确值；加法溢出、减法下溢或预算失败不修改原值 |
| T04.foundation.invariant_fail_fast | 独立子进程触发明确不变量入口，实际非零退出；启动失败或缺DLL不能冒充 fail-fast成功 |
| T05.foundation.name_ascii_bounds | 1和96字节通过；空、97字节、空格、NUL、控制字节、DEL、UTF-8中文拒绝；96字节检查按字节执行 |
| T05.foundation.name_case_and_ownership | Read和read不同；相同字节相等；来源销毁后名称保持，标点按既有0x21–0x7e合同处理 |
| T05.foundation.tagged_identity_types | 同Tag相等/排序符合值语义；TaskId/ObjectId及epoch/业务ID不可隐式互转，跨Tag比较不可用 |
| T05.foundation.identity_canonical_codec | 零值、全1及混合128位值固定32字节往返；大写、连字符、前后空白、非法hex、31/33字节拒绝 |
| T05.foundation.bound_handle_generation | 当前registry世代且slot有效时成功；旧世代、同generation的不同registry、空句柄和边界外slot拒绝，验证先registry身份/世代后索引 |
| T05.foundation.runtime_epoch_separation | 稳定ID编码不含epoch；换epoch后同一业务ID编码不变；epoch数值递增到边界不回绕 |
| T24.foundation.public_headers | 每个公开头独立包含并真实编译；Result可在仅链接Foundation的消费者中使用 |
| T24.foundation.installed_consumer | 安装树搬迁后请求Foundation、编译并运行原语消费者；BUILD_TESTING=OFF构建也可安装消费 |
| T24.foundation.missing_dependency_rejected | 隔离安装副本删除expected头后消费者实际编译失败；不能借用源码/缓存绝对include路径意外通过 |
| T24.foundation.backend_mode_rejected | 隔离消费错误版本/禁用expected异常/无C++异常模式时明确失败；正常锁定模式通过 |

分配统计独立于 Catch2 框架运行：暖机后启用计数，覆盖普通、数组及 aligned new，对应 delete 齐全；显式分配控制例证明计数器工作。报告测量窗口、配置和计数，不把测试框架初始化或诊断输出分配计入 Foundation。注入 OOM 与统计程序可以独立，避免拦截器互相干扰。

## 六项集成调整

1. **阶段与架构检查演进。** Foundation 实现状态显式推进，保留 INTERFACE_LIBRARY，其余20个组件保持 ContractBaseline。架构反例继续拒绝 Runtime伪报实现、越层依赖和未知目标。更新规则的反例先于生产修改，不能为通过测试整体删除基线保护。
2. **公开头清单与审查。** foundation.hpp从candidate_headers移到headers，登记实际hash、所属target、experimental分类；所有拆分公开头同样处理。同步中文公开表面、所有权、异常和线程语义说明，不将hash相等当成ABI兼容证明。
3. **expected真实公开依赖及安装。** Foundation在BUILD_TESTING=OFF时也取得锁定expected，复用离线hash校验；导出正确build/install include与公共目标，安装tl/expected.hpp和许可证。安装产物不得含源码/缓存绝对路径，不依赖probe开关才使SDK可用。
4. **产品DAG与第三方闭包分离。** Foundation内部dependencies仍为空；额外记录审查过的expected外部依赖。当前graph导出会将所有INTERFACE_LINK_LIBRARIES当作产品依赖，需显式分类并校验第三方白名单；不得忽略任意未知链接，测试/私有实现依赖仍不能混入产品DAG。
5. **组件发现和消费者。** OCKConfig允许COMPONENTS Foundation，Runtime和未知Observation仍明确拒绝；sdk元数据保持runtime_available=false。原D0.02消费者检查从绑定历史文案演进为稳定行为检查，并保留安装搬迁/缺组件反例。
6. **单后端与工具链模式。** 公开合同记录tl::expected1.1.0、C++20、CRT和异常模式；检查后端版本、_CPPUNWIND及TL_EXPECTED_EXCEPTIONS_ENABLED。公开编译要求的变化同步进入manifest和实际graph校验，Debug/Release不能混CRT；不宣称跨工具链二进制ABI受支持。
