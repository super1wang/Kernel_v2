## ResourceWaitBinding 无丢唤醒协议（B5 必须实现）

以下将原接线计划收敛为一个拥有型、有限状态的 Runtime 内部协议，不增加第二 Task、第二资源管理器或第二套业务 Handler。Binding 状态与 ExecutionPhase 分开；`Binding.Terminal` 仅表示该 binding 不再准入/重试，**不自动表示 Execution Terminal、业务已停止或 Host quiescent**。

1. **先准备，后发布接受，最后允许执行。** 先预留 ExecutionRef、拥有型输入/结果或最小回执、执行记录、可靠完成容量和 binding owner；准备完成/摘除回调，再发布 `resource_ready=false` 的 Scheduler entry 并取得稳定 ticket。enqueue 失败不申请资源、不发布 Accepted。enqueue 内的 wake/completion 可早于返回，预建 owner 必须暂存内部完成事实；不能因为早到回调就访问未安装 ticket。Scheduler ticket 发布后，在任何 `make_ready`/业务运行前完成 Volatile Accepted 的内存发布。接受发布前中止须禁止 start 并回收内部条目；接受发布后即使立即过期、资源失败或 Executor 拒绝，也保留同一 ExecutionRef 的失败事实。快速完成可以先于客户端收到 Accepted，但不能先于服务端完成接受发布。Scheduler ticket 不是 ExecutionRef，也不是客户端授权凭证。

2. **依赖就绪先于申请业务资源。** 稳定 ticket 已发布只是必要条件；还须确认准入仍有效且当前阶段的执行依赖已满足，才启动 acquire。不得让仍等待前驱的后继预占前驱所需资源；不得在 WaitingChild 中继续持有 child 必需资源。依赖满足/失败仍由既有 Scheduler 的可靠依赖仲裁给出，B5 只增加必要的窄接线，不复制一份可漂移的依赖计数。不以遍历历史或反复轮询等待依赖。没有依赖的 entry 可在接受发布后直接进入资源准入。

3. **拥有者、世代与驱动者明确。** Binding 归 Runtime Execution owner；记录 ticket、单调 `attempt_generation`、WaitingDependencies/Installing/Waiting/Retrying/Ready/Terminal 阶段、wake_pending、ResourceManager 的 `waiter_generation`、owning waiter 与 optional lease。Binding generation、资源 waiter generation 与 Scheduler dispatch attempt 是不同用途的字段，不能混用或从客户端取值；失效世代不复用，耗尽明确失败。每次 acquire 前在同一 binding 仲裁下预留新 attempt，再解锁调用。不得持 Scheduler/binding 锁调用 ResourceManager，也不得持 binding 锁调用可能同步 signal/completion 的 Scheduler 方法；资源锁下不回调 Scheduler。进入外部调用或析构前完成本地状态提交并持有局部 owner，返回后只操作仍有效状态。

4. **早到 wake 只记账，不递归执行。** wake 持有或临时取得有效 binding owner，并携带所属 attempt 与资源 generation。仅活跃 attempt 可以登记 wake_pending；Installing 阶段只记账。acquire 返回后，在 binding 仲裁下分类结果；若返回 waiter，核对该 waiter 的资源 generation 与 pending wake；已 pending 则移出旧 waiter，转入唯一 Retrying，锁外取消后重新申请全部 claims。Waiting 阶段的 wake 也先通过同一仲裁取得唯一重试驱动权。回调期间、返回安装期间以及旧 waiter 销毁期间，重复/迟到 wake 都不能生成第二驱动者。所有强持有回路须由终止/关闭显式拆除，不能仅依赖析构；资源永不释放时，关闭仍须能撤销等待。

5. **完整分类 acquire 结果。** 空 claims 是合法的“无业务资源需求”，绕过 ResourceManager::acquire，既不创建空 Lease，也不制造占位资源。成功返回 lease 时进入资源就绪；成功返回 waiter 时进入有界等待。InvalidInput、UnknownKey、Overflow、PhaseViolation、Closed、Full 等非等待结果按接受边界形成明确拒绝或失败事实，不无限重试、不重新挂空 waiter。WouldBlock 不能冒充成功；需要等待的接线应使用带 wake 的 acquire，取得真实 waiter，否则明确结束/报告未取得等待能力。失败返回不能同时安装 lease/waiter。wake 只提示重新申请完整 MultiClaim，绝不代表已授资源。

6. **取消请求不等于终止，不得提前释放运行期 Lease。** `cancel_requested`、获取 attempt 失效、Scheduler Started、Execution Finalizing/Terminal 和物理 quiescent 分别表示。B5 的逐执行取消必须与既有 start claim 接通：取消若赢得“尚未开始”的权威仲裁，才允许阻止 start、使 binding generation 失效，并锁外移出/释放未交给业务的 waiter/lease；若 start 已赢，取消只更新协作意图/期限，不能通过普通取消路径调用运行期 Lease::release。不得在两个独立锁下先查询 Started 再释放 Lease，形成检查后使用竞态。进入任何业务代码前，typed 执行适配必须在有效的开始/取消协议下取得独占或明确共享的运行期 lease owner；同步函数返回并退出相关访问，或异步完成/子执行访问真正排空后，才归还这份 Lease。只保活 Lease 对象不足以防止其他路径显式 release，释放权限也须唯一。

7. **安装与 make_ready 的交接。** acquire 在途时可先失效 attempt，但 owner 保持到返回；失效返回的 waiter/lease 立即在锁外取消/释放，不安装、不 make_ready。有效 lease 先装入 binding、进入 Ready，再锁外 make_ready(ticket)。make_ready 可能同步 signal 并导致 inline 完成，调用前须持有局部 binding/Execution owner；返回后不能假定仍为 Ready。失败清理只移出仍属于本 attempt、尚未转交运行期 owner 的 Lease；已经由完成路径移出者不得重复释放。无资源分支使用同一接受/取消/start 规则。尚未 Started 的 acquisition 失败/取消还须退役 Scheduler entry，不能只释放 waiter、遗留永远 resource_ready=false 的条目；逐票据退役与 start/cancel 的窄接口在 D3.04/D3.05 实现，不冒称当前 make_ready/close 已经提供该能力。

8. **可靠推进与实际排空。** 所有重试采用有界迭代或 continuation，不在资源 release/capture 析构栈无限递归。每 entry 采用合并 pending 位及可证明不丢失的唤醒协议；若使用队列，其可靠完成/重试容量在接受前预留，不能因 post_control 队列满而丢 wake，也不能用无限轮询补偿。每轮重试与控制处理有有限工作预算，满载仍能受理取消/停止。终止后逐步收回 waiter、lease、acquire-inflight、callback owner、运行期访问与投递 envelope；逻辑终止时允许仍有已计费的在途收尾，**worker_delivery 仅随 envelope 实际收尾归还**。内核可靠完成独立于可丢通知；取消订阅、断线或最后一条通知丢失不影响执行事实。

### 必测交错与判定口径

| 交错 / 反例 | 必须证明 |
|---|---|
| enqueue 返回前完成、接受发布与资源就绪/inline 竞争 | 接受前业务不运行；接受后失败保留同一身份；已完成可以先于 Accepted 响应送达，不能先于内存接受发布 |
| 前驱 P 与后继 C 都需要 R，C 依赖 P；刻意延迟 P 的资源申请 | C 在依赖未满足时不占 R，不形成 P 等 R、C 等 P 的循环；依赖失败精确结束后继 |
| wake 早于/晚于 waiter 安装，旧 wake 晚于新 attempt，重复 wake | 单驱动、世代正确、无丢唤醒、无重复 requeue；验证有界重试和控制通道满载 |
| deadline/cancel 在 acquire 前、在途、安装前后，以及与 start claim 同时 | 仲裁只有一个有效结果；未开始无业务副作用；已开始仍持有运行期 Lease，协作结束后才释放 |
| 空 claims、合法未知键、Full/Closed/永久参数错误 | 无资源操作可执行；错误不会无限重试；已发布内部 entry 最终可退役，接受后身份不丢失 |
| make_ready 失败、回调早于 make_ready 返回、资源回调/capture 析构重入 | 无返回后悬空访问、双释放或已终止 attempt 复活 |
| 取消/过期后 Executor 仍持有已接受 envelope | 逻辑完成不虚减 delivery；实际收尾后准确回收；正常失效投递不被当作违规 Executor |
| 资源永不释放时 Host 关闭，强持有回路、慢完成与迟到回调 | 显式取消 waiter，保留在途 owner；超时不报告排空，不 detach，不销毁仍使用的依赖 |

使用受控屏障验证两种先后，并补真实线程与 ASan；不能只靠 sleep。按阶段断言：失效后不新发起业务；在途时 owner/额度仍保留；真正 quiescent 后本次执行持有和 waiter/index/delivery 回到基线。存在其他任务时不得要求全局 used 等于 0；仅在所有任务和回调均排空的隔离场景断言全局归零。

### 跨包接线约束

- **同一业务和当前授权。** Submit 复用已注册 typed 实现与原有参数/目标/权限合同，不把原本只能在合法线程直达的 HostBound::invoke 生硬投递到 CPU worker，也不为通过线程检查而放宽 Native 合同；在既有 InvocationEngine 内补受管理执行路径。Execution 的 owner/delegation/实际 claims 来自可信材料，入队时许可不代替执行/效果决定点的当前检查。get/wait/list/cancel/结果读取及发送按当前权限分别授权，撤权不泄漏已排队敏感结果。
- **等待与父子。** wait_timeout、transport_timeout、execution_deadline 分开；CLI Ctrl+C/退出默认只停止等待和订阅，不取消服务端执行。worker/control/domain/DB 的非法阻塞等待仍拒绝；WaitingChild 用 continuation 并释放 child 必需资源/执行配额。父 Terminal 前 child 必须完成或按既定可信独立 owner 策略接管；不增加任意 detached 执行。
- **观察和保留。** 非终态含 Finalizing/Suspended；ExecutionSummary/phase/fact/version 一致发布，Terminal 不重开。内部完成和必要收尾不依赖任何订阅 ACK、网络发送或客户端确认；慢观察者不扩大结果 pin。执行表、输入/结果字节、完成槽、等待者、索引和终态保留分别有界；按 A21 初值，普通终态热缓存采用 10,000 条或 64 MiB 先到者，仍被必要引用的材料不可普通淘汰。listing_ordinal 在宿主世代内唯一递增不复用；分页仍有界、必前进，复用既有 cursor 身份/首次 TTL/无状态语义。
- **正常失效不等于 Executor 违约。** 当前 Scheduler::Work::execute 将 generation 失效/terminal 与重复 execute 一起计入 executor_violations；当已接受 work 先因期限失效、随后由合规 Executor 首次调用时，会发生诊断误计。D3.05 在扩展取消仲裁时一并区分“正常失效后的首次 no-op”和“重复执行、拒绝/异常后仍调用”等真实违约；保留一次执行尝试与释放的防御。新增正负例，不用关闭全部检测来消除误报；在此之前不得仅按该累计数自动隔离后端。本项是当前源码诊断缺陷的 B5 内修复，不重新升级为前置门禁。
- **必要收尾范围。** B5 的 permit/commit 竞争、必要记录失败和故障隔离使用既有窄端口及受控注入验证；不以此声称 State/SQLite/真实外部效果/恢复已经实现。业务完成、必要收尾完成、外部通知和物理排空分别计量；shutdown_until 超时继续保活依赖，后续由合法控制 owner 完成排空和回收。

### D3.07 Control Submit 接线（2026-09-10，编码前）

### D3.06 必要记录接线（2026-09-10，编码前）

可信执行组合可选装配既有 RequiredRecordPort；每个执行在 Accepted 前预留固定上限的记录请求、记录 reservation 和 owning receiver。当前 Read 路径记录执行收尾事件及身份，不据此把业务返回值声明为 Durable。候选结果到达后由共享控制循环调用记录器一次，记录成功/失败与 receiver 实际排空分开；缺失、错误身份、抛出及失败报告均形成可查询记录故障。失败先封锁该执行服务的新准入，再发布 RequiredRecordFailed；既有 get/wait/cancel 与在途收尾继续可用，不把尚未实现的 State/Effect 写入后端称作已验证。

Outcome 只允许追加必要记录状态，不修改既有业务值、事实或取消结果；Pending 不能对外发布为 Terminal，Failed 要携带真实准入封锁和 ManualReview。父子、业务 owning callback 及记录 receiver 全部排空才终态；不以返回 record() 或接到 completed() 代替物理排空，不在内部锁下调用记录器或销毁其 owner。直接验证真实 Host 的成功/失败/缺失/重复/错误身份/重入及关闭超时，并保留原业务结果。

### D3.05 运行期期限接线（2026-09-10，编码前）

ExecutionService 在接受前为每个活动执行预留一个定时节点；共享控制线程按有限批次处理到期，不另建线程或扫描终态库。排队与运行期共用单调 deadline；开始时当前 Policy 收紧的期限通过内部 scope 传回，节点只缩短、不延长，并复用原节点更新。到期在服务锁外提交同一协作取消意图，覆盖异步 callback 和结构化 child；不提前释放 Lease，不覆盖已完成事实。创建失败/实际终态归还节点，接受发布与服务安装之间到期必须在安装后补取消。直接验证真实运行中的同步/异步取消及 callback 持有时不早排空。

### D3.06 父子接线实施细化（2026-09-10，编码前）

沿用同一 typed Handler 和 ExecutionService，`WorkContext` 仅在受管理运行期携带真实执行 scope；公开 `HostBound::submit_child` 使用该 scope，Runtime 校验同一执行服务、同一 SessionAuthority/主体及当前授权，child 的单调期限不得超过父期限。客户端自造 scope、跨服务 scope、父调用已退出或取消后的创建均拒绝。每个父执行预留有限 child 槽，嵌套深度有界，child 新身份/parent/owner 在接受前固定；不提供任意 detached 或接管入口。

父调用栈退出后关闭 child 创建，释放同步运行期 Lease 和 Scheduler worker 配额；尚有 child 时发布 WaitingChild，child 的可靠终态信号只唤醒同一控制循环推进父 Finalizing/Terminal，不占 worker 阻塞等待。child 安装须早于其调度接受，父取消与安装在同一父槽仲裁，排队 child 不因安装竞态漏掉传播。失败创建撤销父槽，已接受 child 失败仍保留独立回执；child 持有父寿命而父槽仅弱持有 child，终态显式解除关联，不形成强引用环。

直接验证覆盖独立身份/parent、同资源 child 在父返回后进入、父 WaitingChild/不早终态、父取消传播、关闭超时保活、创建失败槽回收、伪造/跨服务/权限主体拒绝、数量/深度上限。外部异步 I/O 完成另沿同一 owner 接入；本节不是异步或 G3 完成声明。

### D3.06 异步 Read 完成细化（2026-09-10，编码前）

新增从实际 owning Handler 签名推导的异步 Read 注册重载，仍是同一 Operation/Execution，保持 AtomicMode::Incompatible；PureCompute 不放宽异步限制。Handler 接收拥有型 AsyncReadCall（输入、WorkContext、Reader、一次性 complete），不得保存调用栈引用。注册目录冻结真实 async 类型见证与私有工厂，接受前准备输入/最小结果/回调 owner，短 Invoke 对该操作拒绝并要求 Submit。

结果 candidate 与回调 owner 排空分开：complete 只发布一次候选结果，重复完成明确拒绝；最后一个 callback owner 释放前不回收输入、Policy admission、调用槽或运行期 Lease。丢弃 owner 未完成须产生失败事实；Handler 返回失败/抛出不能覆盖先到完成。Runtime 继续复用可靠 pending 和有限控制循环，candidate 已到但仍有必要访问时保持 Finalizing，所有 callback/child 收尾后才 Terminal，Host 超时仍保活。只有 complete 支持并发仲裁，业务须串行使用可变 WorkContext。异步父的资源仍由 callback owner 持有时，创建 child 复用 Lease::before_child_wait 的规范化冲突检查，拒绝不安全资源组合；不另建资源图或解除运行期 Lease。

直接验证覆盖 inline/返回后完成、重复/遗漏/抛出完成、结果先到但 callback 仍持有的 Finalizing、输入/服务/Lease 寿命、取消/关闭超时及别名资源冲突。此实现不引入第二 TaskHandler，不以 ASan 代替完整 Embedded/G3。

优先采用低风险的有限 pending 合并、单驱动有界重试、明确 owner 转移和已有冻结 Schema/Catalog 复用；目的分别是避免唤醒丢失/递归堆栈、控制开销和寿命回归，不作未经测量的加速承诺。当前不重写 Shared IOCP、JSON framing、动态字段校验或资源公平算法，不扩张 Evidence/Fixture 框架。controlled executor 只运行确定不会阻塞的测试 work；需要证明真实 drain 截止时使用生产池或受控外部驱动，不能让同步 run_one 掩盖超时。

B5 完成必须同时满足 D3.04–D3.07 各包原完成条件、本版接线反例、真实多进程观察及完整 Embedded/G3；不能把必需项改名 deferred 后宣布完成。最终状态只能由同来源正式实现与机器/技术验收更新。本版只支持 **B5 开发 GO**，不代表 B5/G3 Passed、硬实时或物理设备准入。
