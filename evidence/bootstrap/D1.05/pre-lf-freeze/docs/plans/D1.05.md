# D1.05 Native Invocation 与无任务短路径实施计划

状态：**PendingReview**。本文件细化唯一 v3.3 的 D1.05；候选接口与测试集合尚待独立 AI 规格审核，不是行为实现批准或实际 Passed。

执行方式：使用 subagent-driven-development 的实施与独立规格/代码复核；用户已授权自动验收，不逐节点请求人工批准。沿用当前任务分支和既有证据工具。

目标：真实运行注册目录中的 Read/Compute，经参数、身份、目标、权限、线程准入及结果检查完成易失 Native Invoke，在 A21.5 固定场景中验证每次成功调用框架零新增堆分配。

架构：运行时内部 Invocation 组合不可变 Catalog 与真实 Policy Session；绑定阶段保存类型见证和寿命所有者，调用阶段执行当前治理。业务实现只能由内部受治理分派调用，不能向消费者提取裸 Handler。

技术：C++20、固定 MSVC/Windows SDK、CoreContracts/Foundation、既有 owned Windows Job 证据采集与三配置 CTest。

## 按序实施和验收

本包不把 D1.03 注册 ResourceBinding.owner 当作调用租约。任何非空资源声明的已注册操作，在 invoke 的业务进入前明确 ResourceUnavailable；不因注册 owner 存活而跳过拒绝。固定成功计数场景限定无资源声明；D3.03 的真实获取/调度另包实现。WorkContext 借用模式只提供受信栈视图，不凭可构造 DTO 授权。

计数窗口覆盖完整准入、业务、结果构造和同步观测。MSVC Debug 的空 vector 代理分配属于真实框架成本，不能排除。分别记录 new 系列和 Debug CRT hook 通道，不重复相加；逐入口正控制与固定参与模块/源路径/链接材料共同说明覆盖。Debug CRT 诊断与 Release 的宏、迭代器、CRT、优化差异须明列，不能把无 malloc 导入当作没有间接或 DLL 分配的证明。未覆盖的 Release CRT/自定义堆及 DLL 内部入口明确标明；结论只覆盖已声明配置、模块和窗口。
